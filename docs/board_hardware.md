# DShanMCU-F103 开发板硬件参考

## 1. 开发板概述

- **原理图范围**。本文的板级接线依据用户提供的 `codex-clipboard-0d73f883-00bf-4afd-8133-7e646aaadc00.png`。可见区域包含核心板插座、扩展排针和外设接口。下缘截断，核心板内部电路及外接模块的内部电路待确认。
- **MCU**。项目的 `NWatch-DShanMCU-F103.ioc` 指定 `STM32F103C8T6`、`LQFP48`。芯片型号和封装来自项目配置，原理图截图只画出了核心板接口。芯片复用能力见 ST 的 [STM32F103x8/xB 数据手册 DS5319](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf)和 [STM32F1 参考手册 RM0008](https://www.st.com/resource/en/reference_manual/cd00171190-stm32f101xx-stm32f102xx-stm32f103xx-stm32f105xx-and-stm32f107xx-advanced-arm-based-32-bit-mcus-stmicroelectronics.pdf)。
- **供电**。图中可确认 `VCC_+3.3V`、`VCC_+5V`、`GND` 和 `VBAT` 网络。J1/J3 引出 3.3 V、GND 和 VBAT，J2/J4 引出 3.3 V、5 V 和 GND。外部电源从何处接入、两路电源如何生成、VBAT 的实际来源以及各电源轨的可用电流待确认。3.3 V 与 5 V 分别记录，各插座的供电见第 3 节。
- **接口与功能**。J1/J2 为接核心板的 20 针插座，J3/J4 为对应的 20 针扩展排针，间距均为 2.54 mm。图中有 14 个 M 系列模块接口（M11 的具体模块待确认）、K1 按键、J6–J8 三个舵机接口，以及连接 M14 输出的 J5 电机接口。按功能位置计为 18 处，J5 归入 M14。模块是否实际安装待确认。
- **读表约定**。`M1.3` 表示 M1 的物理第 3 针。GPIO 用 `PAx`、`PBx`、`PCx` 表示。`OUT/INT`、`KEY`、`CS` 等为信号名，`EXTIx` 为 MCU 的中断线，`VBAT`、`NRST` 和电源地单独记录。表内“可用”表示芯片支持的功能，启用状态取决于固件。

## 4. 引脚冲突和复用分析

### 4.1 原理图确认的共线

| 共用 GPIO | 两端连接 | 并用条件 |
| --- | --- | --- |
| `PA1` | M2.2 DS18B20、M10.2 DHT11 | 图注要求不能同时接。实际只接其中一个，软件按所装模块选驱动。两个任务分时执行仍会把波形送到两个插座 |
| `PA8` | M4.1 红外发射、M9.2 蜂鸣器 | 图注要求不能同时接。GPIO/PWM 输出同时到达两个插座，实际只接其中一个 |
| `PB9` | M6.2 `Trig`、M12.5 `CS` | 图注要求互斥操作。可由一个驱动管理者或同一互斥锁串行化访问。若两个模块均接入，片选沿仍会到达 `Trig`，触发脉冲也会到达 `CS`。模块允许的空闲电平和误触发行为待确认，确认前按单模块接入处理 |
| `PA15`、`PB3`、`PA2` | M3.1/M3.2/M3.3 与 J6.1/J7.1/J8.1 逐路共线 | 每对共享同一波形，不能分别设定同一通道的频率或占空比。需要独立控制时逐路选择负载，同时核对三个 TIM2 通道共用的周期 |
| `PB6`、`PB7` | M1 OLED、M11 | 设计为同一 I2C1 总线，R1/R2 分别提供 10 kΩ 上拉至 3.3 V。确认 M11 供电、设备地址互异、总线电平、等效上拉及速率后可并用，任务之间串行化 I2C 事务 |

J3/J4 引出的 GPIO 与 J1/J2 及表中的模块是同一批网络。给扩展排针增加器件时，须把已连接模块纳入电平、驱动方向和总线冲突检查。

### 4.2 MCU 复用与软件限制

以下是芯片功能和固件配置条件。定时器或总线实例能否分配给新功能，需按实际构建配置检查。引脚能力与重映射查阅 [DS5319 引脚定义](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf)及 [RM0008 的 AFIO 和 EXTI 章节](https://www.st.com/resource/en/reference_manual/cd00171190-stm32f101xx-stm32f102xx-stm32f103xx-stm32f105xx-and-stm32f107xx-advanced-arm-based-32-bit-mcus-stmicroelectronics.pdf)。

- **TIM2 和 ADC**。M3、J6–J8 的 `PA15/PB3/PA2` 对应 `TIM2_REMAP=01`（部分重映射 1）。该模式的 CH4 在 `PA3`，接了 M7 时可作为 `ADC1_IN3` 模拟输入，使用 CH4 的外部引脚功能会占用它。TIM2 不重映射时 CH1/CH2 在 `PA0/PA1`，分别与电机控制、温湿度数据线重叠。重映射 `10` 或 `11` 会把 CH3/CH4 移到 `PB10/PB11`，分别与红外接收、光敏模块数字输出重叠。M7 模拟输出接入 ADC 前应确认处于 MCU 模拟输入允许的电压范围。
- **I2C1**。使用默认 `PB6/PB7`。重映射到 `PB8/PB9` 会占用 Echo 和 Trig/CS，板上 OLED 与 M11 的连线仍在 `PB6/PB7`。在 `PB6/PB7` 启用 TIM4 通道输出或重映射 USART1 也会占用总线。若 TIM4 只做内部时基，GPIO 可继续用于 I2C1。
- **SPI1**。使用默认 `PA5/PA6/PA7`，以 `PB9` 作 M12 的 GPIO 片选。默认硬件 NSS 为 `PA4`，该脚在板上用于 M14 的 `AIN1`。SPI1 重映射会占用 `PA15/PB3/PB4/PB5`，分别与 RGB/舵机两路、电机输入和 M11 中断重叠。
- **其他外设复用**。`I2C2` 或默认 `USART3_TX/RX` 占用 `PB10/PB11`，影响 M8 与 M7 数字输出。启用 SPI2 的相关信号会占用 `PB12`（M13）、`PB13`（M5）、`PB14`（K1）、`PB15`（M14）。TIM3 的默认 CH1/CH2 外部引脚与 Flash 重叠，部分重映射后与 M14 的 `PB4`、M11 的 `PB5` 重叠，CH3/CH4 的 `PB0/PB1` 与 M13 重叠。内部计时可独立于 GPIO 复用，仍需统一管理同一定时器的计数频率和周期。
- **SWD/JTAG**。`PA15`（`JTDI`）、`PB3`（`JTDO`/`TRACESWO`）、`PB4`（`NJTRST`）可能被调试功能占用。使用这些模块前核对 AFIO 的 SWJ 设置，选用保留 SWD、关闭 JTAG 的模式，并避免让 SWO 占用 `PB3`。SWD 使用 `PA13/SWDIO` 和 `PA14/SWCLK`，这两根线在图中 J1–J4 未引出。项目 HAL MSP 可见 `__HAL_AFIO_REMAP_SWJ_NOJTAG()` 和 `__HAL_AFIO_REMAP_TIM2_PARTIAL_1()`，实际生效仍取决于构建和初始化路径。
- **EXTI**。`INT` 标签只表示信号用途。`PA1` 和 `PB1` 若均要中断，会竞争 `EXTI1`，可将其中一方改为轮询或用协议驱动读取。`PB10`、`PB11`、`PB12`、`PB13`、`PB14` 分别对应独立的 EXTI10–14 线，但共享 `EXTI15_10_IRQn`，处理程序要按挂起位分发。`PB5` 和 `PB8` 分别对应 EXTI5、EXTI8，共用 `EXTI9_5_IRQn`。按实际信号极性选择触发边沿。
- **5 V 模块接口**。M13 的供电是 5 V，图中信号直连 MCU。`PB0/PB1` 为非 FT 引脚，应先确认其收到的电平在数据手册允许范围内。M14 的 `VM` 和 `STBY` 接 5 V，四路控制信号来自 MCU，驱动板是否可靠识别 3.3 V 逻辑待确认。M6 的 Echo 幅值以及其他替换模块的信号电平也要按实物确认。

## 5. FreeRTOS 开发参考

以下为任务规划。当前工程的 `Core/Src/main.c` 让 GUI 任务负责 OLED 初始化和绘图，并使用 TIM3 微秒计时、TIM4 HAL 毫秒时基。部分外设初始化受 `NWATCH_UI_ONLY` 条件控制。分配定时器或 IRQ 前，按当前目标的源码、构建选项及 `FreeRTOSConfig.h` 核对。

| 功能 | 硬件接口与 GPIO | 任务与资源约束 |
| --- | --- | --- |
| OLED 显示 | M1，`PB6/PB7`，I2C1 | GUI 任务持有显示状态，其他任务通过队列提交刷新数据。接入 M11 后使用同一 I2C 总线管理者或互斥锁 |
| 按键扫描与编码器 | K1 `PB14`，M13 `PB1/PB0/PB12` | 周期采样、消抖并上报事件。接 M13 前确认电平，启用 `PB1` 中断时检查 `EXTI1` |
| 红外接收与避障 | M8 `PB10`，M5 `PB13` | M8 在 EXTI 中记录边沿和时间戳，任务解码。M5 可轮询或接收边沿事件。两者共用 EXTI IRQ，需按线分发。发射另用 M4 `PA8`，与蜂鸣器二选一 |
| 温湿度与温度采集 | M10 DHT11 或 M2 DS18B20，`PA1` | 只初始化实际安装的一个驱动。由周期任务触发采样，微秒级协议阶段使用可核实的计时源，结果通过队列或通知发布 |
| 蜂鸣器控制 | M9 `PA8`，可用 `TIM1_CH1` | 任务接收提示音命令。确认模块类型再选电平控制或 PWM。与 M4 二选一 |
| 超声波测距与 Flash 存储 | M6 `PB9/PB8`<br>M12 `PA5/PA6/PA7/PB9` | 集中管理 `PB9` 和 SPI1 事务。Echo 可用 EXTI 加时间戳。若改用 `TIM4_CH3` 捕获，需验证现有 HAL 时基的计数配置和 IRQ 可共用 |
| 光照采样 | M7 `PA3` / `ADC1_IN3`、`PB11` / 数字输出 | 任务周期采样。数字告警可用 EXTI，与 M8 等共享 IRQ。保留 `PA3` 的模拟模式 |
| RGB、舵机与电机 | M3/J6–J8 `PA15/PB3/PA2`<br>M14 `PA0/PA4/PB4/PB15` | 为 TIM2 设一个控制者管理周期和通道。电机驱动另用 M14 的四根控制线，初始化时考虑 `PB4` 的调试复用 |
| 任务间通信与串口 | 内部队列、事件组和任务通知<br>可选 USART1 `PA9/PA10`（J2.15/J2.14 或 J4.15/J4.14） | RTOS 的内部通信无需 GPIO。使用串口收发或日志时由单一任务管理发送，确认所选构建启用了 USART1 |

调用 FreeRTOS `FromISR` API 的中断必须满足当前端口的中断优先级限制。红外、超声波等边沿处理中断只做必要的采样和通知，耗时解码、总线访问或 UI 更新交给任务。

## 6. AI 编程约束

1. 编写驱动前必须查阅本文件，核对模块位号、物理针号、GPIO、供电与信号方向。
2. 不允许擅自更改硬件 GPIO 映射。驱动参数、GPIO 初始化及 AFIO 重映射都必须与已确认接线一致。
3. 使用共用引脚前必须检查第 4 节。遵守物理二选一和互斥操作要求，并验证挂接模块及扩展排针上的负载。
4. 配置 GPIO 时必须考虑 ADC 模拟模式、I2C 开漏、SPI 信号方向、TIM 通道和重映射、EXTI 来源及 SWD/JTAG 占用。
5. 原理图无法确定的内容必须标记为“待确认”，禁止编造。模块型号、供电、地址、输出电平、时序等参数应以完整原理图、模块资料或实测补证，并保留来源。
